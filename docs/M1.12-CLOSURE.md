## Scope

M1.12 adds a reusable recovery contract harness for implementations of `PersistenceBackend`.

The harness validates fresh-instance reconstruction over the same durable state without defining a universal constructor or exposing physical storage details through the semantic contract.

It checks:

- committed generation and block state survive reconstruction;
- a committed transaction remains reconcilable by the same `TransactionId`;
- an uncommitted prepared transaction is recovered as `Aborted`;
- recovered `Aborted` state retains `PreparedState` and can retry publication with the same `TransactionId`;
- an explicitly discarded transaction remains discarded after reconstruction.

## Boundary

Construction remains backend-specific through a supplied factory closure.

No new physical backend, platform adapter, storage format, filesystem API, universal constructor, or semantic change was introduced.

The established meanings of `Prepared`, `Committed`, `Aborted`, `Unknown`, `Generation`, and durability remain unchanged.
