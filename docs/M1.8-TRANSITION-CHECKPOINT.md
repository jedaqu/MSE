## M1.8 delivered

The public core now defines the minimum backend-neutral persistence/durability boundary:

- `CommitOutcome::Unknown` retains both `TransactionId` and target `Generation`;
- `DurabilityRequirement` distinguishes publication-only from publication-plus-durability requirements;
- `DurabilityState` distinguishes pending, durable, and unknown durability status;
- `DurabilityObservation` binds a durability state to the same transaction and published generation;
- durability cannot be claimed from an aborted or publication-unknown outcome.

## Boundary verified before transition

M1.8 remains backend-neutral. It introduces no storage trait, persistent store, journal, filesystem or block-device integration, physical addresses, durable identifier encoding, recovery database, kernel/driver code, operating-system-specific adapter, or networking.

## Next phase gate

M1.9 may introduce the first experimental persistence backend.

The backend must preserve:

1. atomic logical visibility;
2. `Committed` / `Aborted` / `Unknown` publication outcomes;
3. same-transaction reconciliation for unknown publication;
4. explicit durability acknowledgement;
5. immutable state/object sharing semantics already established by M1.6;
6. no presentation of partial physical writes as a committed generation.

The first backend must be treated as an experiment against this contract, not as a reason to weaken or redefine it after implementation.
