## M1.6 delivered

The repository now contains a process-local object identity foundation:

- `ObjectStore` interns identical immutable blocks once per store;
- `StateRoot` maps logical block positions to shared `ObjectId` references;
- replacing one root reference preserves every unchanged reference;
- store identity prevents roots from being applied to another object store.

The model remains entirely in memory.

## Boundary verified before transition

M1.6 does not introduce persistence, durable content addressing, physical addresses, storage backends, filesystem or block-device integration, kernel or driver code, operating-system-specific integration, networking, or commit/recovery semantics.

## Next phase gate

The next gate must define at least:
- observable commit outcomes: `Committed`, `Aborted`, and `Unknown`;
- transaction identity;
- atomic visibility of a committed generation;
- retention of pending state after an unknown or aborted result;
- durability boundary;
- reconciliation/retry semantics.

No backend implementation is authorized by this checkpoint.
