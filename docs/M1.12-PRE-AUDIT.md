## Audit finding

M1.10 established the backend-neutral operational contract through `PersistenceBackend`. M1.11 converted the in-process semantic guarantees into a reusable behavioral harness.

A remaining contractual gap is recovery across backend reconstruction:

- `PersistenceBackend::reconcile` explicitly describes reconciliation after recovery.
- The concrete `FileBackend` already supports durable reopen and recovery through its backend-specific `open` path.
- The current backend-neutral contract has no generic way to exercise a fresh backend instance against the same durable state.
- Consequently, future backends can satisfy the operational harness while still having an incorrect reopen/recovery implementation that is only caught by backend-specific tests.

This is a real testability gap because recovery is part of the established semantic contract, but it is not yet evidence for a new physical backend or a broad construction framework.

## Scope decision

M1.12 is limited to a reusable **recovery contract test harness**.

The harness will:

- create and mutate state through `PersistenceBackend`;
- close the backend instance;
- obtain a fresh instance through a supplied backend-specific factory;
- verify generation and committed state survive reconstruction;
- verify an uncommitted prepared transaction is recoverable as `Aborted` and can retry with the same `TransactionId`;
- verify an explicitly discarded transaction remains discarded after reconstruction.

The harness will not:

- define a physical storage format;
- add a second backend;
- add a platform-specific adapter;
- introduce a universal constructor/configuration abstraction;
- expose filesystem operations through the backend contract;
- change the established semantics of `Prepared`, `Committed`, `Aborted`, `Unknown`, `Generation`, or durability.

## Minimal design

Construction remains backend-specific. The reusable semantic layer receives a factory closure that returns a fresh implementation of the same `PersistenceBackend` over the same durable state.

This keeps physical configuration outside the semantic contract while allowing recovery guarantees to be tested uniformly.

## Exit criterion

M1.12 is complete only when the recovery harness passes against `FileBackend`, existing semantics remain unchanged, the repository CI is green, and the result is documented with post-merge evidence.
